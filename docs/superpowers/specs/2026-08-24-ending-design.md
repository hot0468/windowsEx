# 엔딩 — 설계

2026-08-24. 다섯째 날 퇴근 뒤에 이어지는 엔딩과, 게임 곳곳에 미리 심는 이스터에그.

## 진실

플레이어(김한별)는 휴가 마지막 날 새벽 귀경길 사고로 죽었다. 자신이 죽은 줄 모르고
출근해 닷새 동안 일하는 환영을 본 것이다. 퇴근길의 괴담(b11)은 옆자리 동료가 그
빈자리를 보고 쓴 글이고, 팀장·팀원의 "쉬엄쉬엄 해요"는 걱정이 아니라 보내는 말이며,
엄마가 보낸 귤과 입금은 제사상과 노잣돈이다.

## 두 갈래

- 결정적 사건: 받은편지함의 `mail_obituary` — 제목은 "[인사총무팀] 8월 넷째 주 경조사
  안내"로 평범하고, 본문에 본인 부고(8/22 새벽 귀경 중 사고)가 적혀 있다. 여는 순간
  `store.witness()`: `clue_mail`을 소리 없이 grants에 기록하고 2.6초 뒤 팀장이
  "김대리. 그 메일은 열지 않아도 돼요. 오늘은 그만 쉬어요. 정말로요."를 보낸다(한 번만).
- `awareOf(ending, grants)`: `clue_mail`이 있으면 진실 엔딩(`ending.true`), 아니면
  평범한 주말 엔딩(`ending.plain`: 금요일 퇴근 → 지현과 맥주 → 엄마에게 "토요일에 갈게" → 귤은 엄마 집
  식탁에서 → 월요일 출근). **죽음은 인지했을 때만 사실이다**: 진실 엔딩 밖의 어떤 결말도 죽음을
  암시하지 않는다. `ended`에 `'true' | 'plain'`.
- 뉴스 기사(`n_accident`)와 퇴근길 괴담(b11)은 그 메일로 이끄는 힌트일 뿐 판정엔 안 쓴다.

## 과로 엔딩

- `store.locks`: 화면이 잠긴 횟수(수동·자동 모두, PROGRESS에 포함). 닷새 동안 0이면
  자리를 한 번도 뜨지 않은 것.
- `endingFor(ending, {grants, locks})`: 부고를 열었으면 `'true'`, 아니면 `locks === 0`이면
  `'overwork'`, 아니면 `'plain'`.
- `ending.overwork`: 순수한 일중독 결말. "닷새 동안 화면은 한 번도 잠기지 않았습니다" → 정보보안팀
  "잠금 기록 0회, 보안교육 재이수" → 팀장 "주말엔 회사 오지 말아요" → 퇴근길 "복귀한 사람 주말에도
  출근함 ㄷㄷ" → 월요일 보안교육에서도 메신저 답장. 타이틀 **야근**.

## 로또 엔딩

- 기사 `n_lotto`(8/21): 1100회(7/18 추첨) 1등 100억 미수령, 역삼동 편의점 판매, 지급 기한 8/28.
- 조각(일련번호 3141-5926-5358-9793): 문서/개인/로또.txt "3141-5926-****-****" → 톡톡 지현 "셋째 묶음
  5358" → 휴대폰/다운로드/동행복권_구매내역_캡처.txt "****-****-****-9793". 우리카드 봇의
  "07/18 씨유 역삼점 (동행복권)"과 기사(1100회, 역삼동 편의점)가 내 복권임을 잇는다.
- 사이트 `dhlottery.co.kr`(layout `lotto`, 공개): 일련번호 한 칸 → `serialFits`(하이픈·공백 무시). 1등이면 `grant('lotto')`와 수령 조건 안내(본인 방문, 기한 8/28).
- `endingFor`: `true` > `lotto` > `overwork` > `plain` — 부고를 연 뒤에는 로또가 무효(사이트도
  "본인 확인 불가, 명의 말소"로 응답하고 grant를 주지 않는다). `ending.lotto`는 **유일한 해피엔딩**이며 죽음
  서사를 뒤집는다: 당첨 확인 → 가방 구석의 구겨진 용지 → 8/28 은행 수령 기사 → 인사총무팀
  "부고란에 오기가 있었습니다. 김한별 대리는 건강히 근무 중" → 팀장 "진짜로 쉬러 가네요,
  사직서는 월요일에" + 엄마 "귤은 그만 보내도 되겠다" → 퇴근길 "그 자리 사람 로또 맞고 퇴사함,
  퇴근 빈칸은 근태 버그" → "오늘 처음으로 제시간에 퇴근. 엘리베이터는 1층에 섰습니다." 타이틀 **퇴사**.

## 야근

- 하루 요청을 다 끝내면 퇴근 화면 전에 야근 제안이 뜬다(`scenario.overtime`: title/lines/
  stay/leave/note + `days[n] = {opening, requests[3], asks[3]}`).
- `workLate()`는 `overtime[day] = true`로 표시하고 팀장 오프닝과 요청 셋을 메신저로 흘린다.
  `goHome()`은 `false`로 닫는다. `requestsOf(scenario, day, overtime)`가 야근분을 포함하므로
  `dayDone`도 자동으로 늘어난 목록을 본다.
- 닷새 전부 야근(`workedEveryNight`)이면 과로 엔딩. 기존 "잠금 0회" 조건과 OR.

## 권고사직

- `slips`: 메신저·메일의 모든 오답을 주 단위로 누적(날짜 리셋 없음). **UI에 노출하지 않는다.**
- `laidOff(layoff, {slips, overtime}, scenario)`: 그 주에 실제로 받은 전체 요청 수(야근 포함)의
  `ending.layoff.ratio`(0.9) 이상이면 발동. 인사팀 통보 오버레이 → 선택 둘:
  `quit`(퇴직금 2배, 실업급여 없음) / `fired`(경영상 해고, 실업급여). `ended = 'layoff:<id>'`,
  `Ending.jsx`가 해당 choice의 scenes/end를 그린다. 거래처 3회 실패 화면이 우선.

## 검색 포털 첫 화면 기사란

- `latestNews(news, 6)`: 날짜 내림차순 6건. 검색창 아래 "주요 기사"로 표시, 클릭하면
  기사 페이지. 사고 기사(8/22)가 여기 올라와 있어 힌트가 눈에 띈다.

## 트리거와 상태

- `store.ended` (PROGRESS에 포함) · `endGame()`.
- `finishDay`는 다음 날이 없으면 재시작 대신 `endGame()`. 퇴근 오버레이의 "마지막 날"
  문구는 없애고 버튼을 항상 보여준다.
- `App`: `ended`면 `<Ending />`만 그린다. "처음부터"는 `newGame()`.
