# 메일 예절 검사 — 설계

## 무엇을

플레이어가 보내는 메일이 회사 메일 관례를 지키는지 검사한다. 어기면 박 팀장이
"거래처에서 연락 왔다"며 잔소리한다. 가이드라인은 어디에도 명시하지 않고
작성 화면의 **플레이스홀더로만** 흘린다 — 플레이어가 스스로 읽고 따라야 한다.

검사 항목 세 가지:

| 사유 | 검사 대상 |
|---|---|
| `subject` | 제목에 `[AR주식회사]` 말머리 |
| `greeting` | 본문에 인사말 **그리고** `~입니다` 자기소개 |
| `closing` | 본문에 끝맺음말 |

## 경로에 따라 무게가 다르다

메일에는 두 경로가 있고, 예절이 갖는 무게가 서로 다르다.

| 경로 | 말머리 | 인사말 | 끝맺음말 | 위반 시 |
|---|---|---|---|---|
| **발신** (3일차 `fetch`) | 검사 | 검사 | 검사 | **반려** + 잔소리 |
| **답장** (1~5일차 `goal`) | — | 검사 | 검사 | 정상 접수, **잔소리만** |

**발신은 본퀘스트다.** 3일차에 플레이어가 먼저 C테크에 자료를 요청하는 메일로,
예절을 어기면 김영민이 "어떤 용건이신지 정식으로 다시 보내달라"며 되돌려 보낸다.
기존 동작을 그대로 유지한다.

**답장은 사이드퀘스트다.** 매일 있는 주 과제이므로 여기에 새 실패 조건을 얹으면
난이도와 해고 엔딩 밸런스가 통째로 흔들린다. 예절을 어겨도 메일은 그대로 나가고,
거래처는 정상 회신하고, 목표도 정상 처리된다. `misses`/`slip()`/`failed` 어디에도
손대지 않는다. 박 팀장 잔소리만 뒤늦게 따라온다. 첨부·금액을 틀리는 업무 실수와
매너 실수는 다른 층위의 일이라는 것이 이 구분의 근거다.

답장 제목은 원 제목을 그대로 따르는 형식(`RE: [C테크] …`)이라 편집 대상이 아니고,
따라서 말머리 검사도 하지 않는다. 자기 회사 말머리를 답장에 덧붙이는 것은
실무 관례도 아니다.

## 검사 (`src/engine/goal.js`)

```
checkEtiquette(etiquette, { subject, body, outbound }) → ['subject'?, 'greeting'?, 'closing'?]
```

위반 사유를 배열로 돌려준다. `outbound`가 거짓이면 `subject`는 검사하지 않는다.
`greeting`은 인사말 목록 중 하나 **그리고** 자기소개(`입니다`)가 둘 다 있어야 통과한다.
자기소개의 위치는 제약하지 않는다 — 인사말과 같은 줄이어야 한다는 식으로 조이면
정답 문장이 하나로 굳어 버린다. 기존 `norm()`(공백·쉼표 제거)을 그대로 쓴다.

`checkOutbound`의 기존 `rude` 분기는 사유를 셋으로 나눈다. `rude` 하나가
`subject`/`greeting`/`closing`이 되고, 각각 다른 거래처 회신과 다른 잔소리를 갖는다.
기존 잔소리가 "인사도 끝맺음도 없이"라고 콕 집어 말하는데 말머리만 빠진 경우에
그 대사가 나가면 말이 맞지 않기 때문이다.

`checkGoal`(답장 판정)은 **건드리지 않는다.** 예절은 판정 흐름 바깥의 별도 경로다.

## 데이터 (`scenario.etiquette`)

규칙은 전체 메일에 걸리므로 특정 날짜 안이 아니라 최상위에 둔다. 지금
`days[2].fetch` 안에 있는 `greetings`/`closings`는 여기로 올린다.

```
etiquette: {
  subjectTag: "[AR주식회사]",
  greetings: [...],
  intro: "입니다",
  closings: [...],
  nags: { subject: [3줄], greeting: [3줄], closing: [3줄] }
}
```

`nags`는 박 팀장이 한 줄씩 타이핑해 보내는 메시지다. 요청받은 톤 — 거래처에서
연락이 왔고, 태도가 문제였다 — 을 사유마다 다르게 쓴다. **정답 문자열을 그대로
적지 않는다**: "제목에 회사명을 붙이라"고는 하되 `[AR주식회사]`라고 쓰지 않는다.
잔소리가 곧 정답표가 되면 플레이스홀더로만 흘리기로 한 의미가 없다.

발신 경로의 거래처 회신(`fetch.rudeReply`)도 사유별로 나눈다.

## 발동 (`src/engine/store.js`)

`sendReply`에서 성공/실패 판정과 무관하게 예절을 따로 검사하고, 위반이 있으면
기존 `nag(lines)`를 그대로 부른다. `nag`는 이미 박 팀장 스레드에 한 줄씩
타이핑해 넣고 토스트까지 띄우는 함수다. 3.6초 지연도 그대로 두면 거래처 회신이
먼저 도착하고 잔소리가 뒤따르는 순서가 맞는다.

위반이 여럿이면 **우선순위 하나만** 내보낸다(subject → greeting → closing).
박 팀장이 한 번에 세 가지를 지적하면 잔소리가 아니라 체크리스트가 된다.

`sendReply`는 `subject`를 받지 않는데, 답장은 제목 검사가 없으므로 시그니처를
바꿀 필요가 없다.

## 플레이스홀더 (`src/apps/Compose.jsx`, `src/shell/shell.css`)

가이드라인이 노출되는 유일한 자리다.

- **제목** — 발신일 때만 `[AR주식회사] 제목을 입력하세요`. 답장은 제목이 자동이라 해당 없음.
- **본문** — 지금 플레이스홀더가 없다. `contentEditable`은 `placeholder` 속성이
  듣지 않으므로 CSS `.mw-body:empty::before`로 넣는다. 회색 텍스트,
  `pointer-events: none`으로 클릭은 통과시키고, 입력이 시작되면 사라진다.

  ```
  안녕하세요, AR 주식회사 ○○○입니다.

  (용건)

  감사합니다.
  ```

## 테스트 (`test/outbound.test.js`, `test/scenario.test.js`)

답이 찾아지는가:
- 세 항목을 갖춘 메일은 위반 0건
- 각 항목을 하나씩 빼면 정확히 그 사유로 잡힌다
- 인사말만 있고 자기소개가 없으면 `greeting`으로 잡힌다
- 답장 경로에서는 제목이 무엇이든 `subject`가 나오지 않는다

답이 새지 않는가:
- `etiquette.nags` 어느 줄에도 `subjectTag` 문자열이 그대로 있지 않다

플레이스홀더를 그대로 베껴 쓰면(`○○○입니다`) 자기소개 검사를 통과한다. 이것은
의도된 동작이다 — 플레이스홀더는 형식을 가르치는 장치이고, 형식을 따랐으면
통과하는 것이 맞다. 본문 플레이스홀더는 CSS `::before`이므로 `innerText`에
잡히지 않아, 아무것도 입력하지 않은 메일이 통과할 위험은 없다.

사이드퀘스트인가 (핵심 회귀):
- 예절 위반이 있어도 `checkGoal` 결과가 달라지지 않는다
- 위반이 여러 개여도 잔소리는 한 벌만 나간다

본퀘스트인가:
- 발신 경로는 예절 위반 시 여전히 `ok === false`이고 첨부가 딸려오지 않는다
