# 기존 요청 40건을 행동으로 바꾸기 — 설계

## 왜

`2026-08-30-deed-asks-design.md`가 행동으로 푸는 요청(`ask.deed`)을 만들고 16건을
새로 넣었다. 그래도 전체 220단계 중 문자열 타이핑이 177단계다(80%). 요청 개수를
늘리지 않고 **완료 방식만** 바꾼다 — 찾는 퍼즐은 그대로 두고, 답을 메신저에 치는
대신 그 답이 있어야 할 자리(시트 칸, 메일, 폴더, 드라이브)에 넣게 한다.

목표: 문자열 177 → 137, 행동 16 → 56. 타이핑 아닌 단계 20% → 38%.

## 범위

- **엔진 수정 없음.** 이미 있는 다섯 동사(`cell` `mail` `move` `rename` `upload`)만 쓴다.
- **pool의 단일 단계 문자열 ask 103건 중 40건**을 deed로 바꾼다. 체인(`then`)·고정
  요청(1일차)·`wedding_venue`·`summons`·파일 ask는 건드리지 않는다.
- objective id와 `grant`는 그대로 둔다 — chatter `after:`, ripples, 엔딩이 그 키를
  보고 있으므로 바꾸면 끊긴다.

## 전환 배분 (40건)

| 동사 | 건수 | 왜 이 수인가 |
|---|---|---|
| `cell` | 14 | 답이 숫자·상태인 요청이 가장 많다. 쓸 수 있는 칸이 20개쯤 있다 |
| `mail` | 7 | 게임 안에 이미 글자로 있는 미사용 주소가 7개뿐이다 (테스트가 실존을 강제) |
| `move` | 8 | 폴더 31개, 후보 파일 넉넉 |
| `rename` | 5 | 이름 규칙을 아는 것이 퍼즐인 요청에만 |
| `upload` | 6 | 미사용 드라이브 페이지 7개 (rule/attend/printlog/demo/contact/closed/triplog) |

## 전환의 모양

한 건은 이렇게 바뀐다. 찾을 것은 그대로고 낼 자리만 바뀐다.

```
전  minseo: "B물산 건이 지금 어떤 상태로 잡혀 있는지 확인 좀 부탁드려요"
    → accept ["납기 조율"]  (발주현황 시트를 열어 읽고 채팅에 친다)

후  minseo: "B물산 건 상태가 시트에 옛날 걸로 남아 있대요. 8월에 나간 게 있는지
     보고 맞게 고쳐 주실 수 있어요?"
    → deed: p2_bstate, objective.cell = {file_xls_orders, "2026", row 1, col 3,
      value "출고 완료"}  (출고내역에서 8/18 건을 찾아 발주현황 칸을 고쳐 저장)
```

고칠 것: `lines`(부탁의 말), `placeholder`(입력칸 자리 안내문), `ok`, `no` 3단계.
지울 것: `accept`, `hintAsk`(정답을 흘릴 수 있으므로 새로 쓰거나 뺀다).
더할 것: 그 objective에 `cell|mail|move|rename|upload` 스펙 하나.

미리 나눠 잡는다.

## 지켜야 할 것 (테스트가 검사한다)

- deed ask에 `accept`·`files`는 없다. `no`는 정확히 3단계, `next: []`, `ok`·
  `placeholder` 필수. 마지막 힌트는 파일·폴더·칸·페이지를 정확히 지목한다.
- `cell`: 그 칸이 실존하고, **현재 값 ≠ 넣을 값**, 현재 값이 다른 요청의 정답이
  아니어야 한다.
- `mail.to`는 게임 안(파일·사이트·메일·메신저)에 글자 그대로 있어야 하고 서로
  겹치지 않는다. `requiredAttachment`가 있으면 `wrongAttachmentReply`, 키워드가
  있으면 `unclearReply`, 언제나 `reply.body`가 있어야 한다.
- `move.into`는 실존 폴더 경로, `rename.name`은 확장자 포함, `upload.page`는
  실존 드라이브 페이지 키.
- 옮기거나 올리거나 첨부하는 파일은 **지금 보이는 것** — `attached`·`deleted`·
  `hidden` 파일은 못 쓴다.
- 대사와 안내문은 **다른 요청의 정답 문자열을 말하지 않는다**.
- 숨긴 폴더 안을 봐야 하면 마지막 힌트에 '숨긴 항목'이라는 말이 있어야 한다.

## 난이도

전환한 요청의 `before:3` / `after:4` 태그는 그대로 둔다. `before:3`이던 것은
어디를 어떻게 고칠지 친절히 말해 주고, 태그가 없거나 `after:4`이던 것은 고칠 값을
게임 안 다른 자리에서 찾아오게 한다.

## 안 하는 것

- 새 동사(복사·삭제·휴지통 복원·즐겨찾기)와 엔진 수정. 요청 개수 변경. 체인 중간
  단계의 전환. 난이도 곡선(`pool.sizes`) 손질 — 별건이다.
