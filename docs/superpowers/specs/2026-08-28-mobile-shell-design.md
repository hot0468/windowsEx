# 병상 옆 탁자 위의 폰 — 모바일 셸

2026-08-28

## 문제

이 게임은 폰에서 열리지 않는다. 정확히는 열리기는 하는데, 창을 끌어 옮기고
모서리를 잡아 늘리는 물건이 360px 화면에 얹혀 있을 뿐이다. `shell.css` 125KB에
`@media` 질의가 **단 한 줄**(`prefers-reduced-motion`) 있다는 게 그 증거다.
반응형은 빠뜨린 게 아니라 처음부터 없었다.

그런데 폰은 이미 이 게임 안에 있다.

```
fs 루트: 바탕화면, 문서, 다운로드, 휴지통, 휴대폰, 로컬 디스크 (C:)
                                    ~~~~~~
휴대폰/갤러리 (13)  — IMG_2087.jpg …
휴대폰/다운로드 (7) — 항공예약_캡처.jpg, 영수증_0723.jpg …
```

부름이 첫 번째로 묻는 것이 **영수증_0723에 찍힌 시각**(21:48)이다. 마지막으로
회사에 나간 날 밤 술값을 계산한 시각. 그게 지금은 PC 탐색기의 폴더 트리 속
한 항목으로 보인다.

폰에서 보면 그건 **내 기기에 있는 내 영수증**이 된다.

## 하려는 것

김한별이 회사에서 지급받은 업무폰을 만든다. 데스크톱 버전을 좁게 접는 게 아니라
**두 번째 기기**를 만든다. PC와 폰은 같은 사람의 두 물건이고, 같은 저장 파일을
공유하며, 서로 다른 것을 보여준다.

기기 폭이 좁으면 폰 셸이, 넓으면 기존 데스크톱 셸이 뜬다. 같은 URL, 같은 세이브.

**게임 내용은 한 글자도 바뀌지 않는다.** `workday.json` 23k줄, `store.js` 80KB,
목표 188개, 테스트 748개 전부 그대로다.

## 왜 이 자리인가

세 가지가 이걸 가능하게 한다.

**`store.js`에 DOM이 없다.** `answerFits`, `endingFor`, `requestsOf`,
`hostThreads` — 80KB 전부가 순수 로직이다. 셸을 하나 더 만드는 일은 이 파일을
건드리지 않는다.

**셸이 얇다.** Desktop 73줄 + Window 81줄 + Taskbar 120줄 = 274줄. 데스크톱
은유가 사는 곳은 여기와 CSS뿐이다.

**`.win-body { flex: 1; overflow: auto }`** — 앱 34개는 자기가 스크롤되는 상자
안에 있다는 것만 알지, 그게 창인지 폰 화면인지 모른다. 상자를 바꿔 끼우면 앱은
그대로인 채 물성이 통째로 달라진다.

그리고 **CSS에 transition이 2곳뿐이다.** 데스크톱 셸은 의도적으로 정적이다 —
창은 즉시 열리고 즉시 닫힌다. 그게 윈도우다움이다. 뺏어올 애니메이션이 없다는
건 폰 모션이 **완전한 백지**라는 뜻이고, 두 셸이 상반된 물성을 가져도 서로
간섭하지 않는다.

## 구조

분기는 `App.jsx` 한 곳뿐이다.

```
                 App.jsx
                    │
            useViewport()  ← 폭 ≤ 820px 또는 coarse pointer
                    │
        ┌───────────┴───────────┐
   DesktopShell            PhoneShell        ← 분기는 여기 하나
   (기존 274줄)             (신규)
        └───────────┬───────────┘
                    │
              APPS 레지스트리   ← 앱 34개, 수정 없음
                    │
              store.js        ← 로직 80KB, 수정 없음
                    │
           workday.json       ← 23k줄, 수정 없음
```

기존 테스트 748개는 이 분기를 보지 못한다. `store.js`와 시나리오 데이터를
검사하기 때문이다.

오버레이(`Ending`, `Crash`, `Lock`, `Quit`, `Layoff`, `Rumor`, `Fail`)는 분기
위에 그대로 둔다. 이미 전체화면이라 CSS 손질만 필요하다.

### 새 파일

| 파일 | 대략 | 역할 |
|---|---|---|
| `src/shell/useViewport.js` | 20줄 | 기기 판별, `?shell=` 강제 지정 |
| `src/shell/PhoneShell.jsx` | 110줄 | 상태바 · 홈 · 화면 스택 |
| `src/shell/PhoneApp.jsx` | 70줄 | 전체화면 앱 틀, 뒤로/홈 |
| `src/shell/AppSwitcher.jsx` | 50줄 | 카드 스택, 작업표시줄 대체 |
| `src/shell/phone.css` | ~600줄 | 별도 파일 — `shell.css`는 안 건드림 |

## 화면 스택

`PhoneShell`이 스택 하나를 갖는다.

```
[]                          → 홈
['messenger']               → AR톡 목록
['messenger', 'junho']      → 준호 대화방
```

- **앱 열기** = `push`, 우→좌로 밀려 들어옴
- **뒤로** = `pop`, 좌→우로 밀려 나감
- **홈** = 스택 비우기, 축소되며 아이콘 자리로 수렴

**기존 앱은 이 스택을 몰라도 된다.** 앱 내부 깊이(대화방 진입 등)는 이미 각 앱이
자기 상태로 갖고 있다. `PhoneApp`이 선택적 `onBack` prop을 받고, 앱이 주지 않으면
뒤로 = 홈이다.

### 홈으로 가는 세 경로

**하단 홈 인디케이터가 주 경로다.** 그 선은 장식이 아니라 버튼이다. 어느 앱에서든
탭하거나 위로 스와이프하면 홈. 보이는 선은 140×5px이지만 터치 영역은 상하 22px로
잡는다 — 보이는 것보다 누르기 쉬워야 한다.

**뒤로(`‹`)는 얕게만 되감는다.** 대화방 → 목록 → 홈. 좌측 엣지 스와이프도 같다.

이렇게 나누는 이유: 요청 하나를 푸는 데 파일 찾기와 메신저 답장을 오간다. 하루에
그 왕복이 수십 번이다. **뒤로는 얕게, 홈은 항상 한 번에.**

**앱 전환 카드** 바깥의 빈 곳을 탭해도 홈이다.

### 물리 뒤로가기

안드로이드 크롬의 뒤로가기 제스처는 그대로 두면 **게임을 나가버린다.**
`history.pushState`로 가로채 스택을 `pop`한다. 홈에서 한 번 더 누르면 그때
브라우저 기본 동작이 먹힌다. 진짜 앱과 같게 동작하고, 사고로 이탈하지 않는다.

## 폰이 담는 것

폰은 폰이 가진 것만 담는다. 이게 이식을 '적응'이 아니라 '연출'로 만드는 부분이다.

```
📱 홈
├─ 사진      → fs.휴대폰/갤러리    (네이티브, 즉시)
├─ 파일      → fs.휴대폰/다운로드  (네이티브, 즉시)
├─ AR톡 · 톡톡 · 메일 · 브라우저   (그대로)
├─ 설정      → 기기 정보 · 와이파이   ← cmd + hosts 대체
└─ 회사 PC   → 문서/다운로드/휴지통/C:  ← 원격, 일부러 느리게
```

**회사 PC 앱이 핵심 장치다.** `FileExplorer`에 `roots`를 PC의 네 루트로 제한해
넘기고 접속 연출로 감싼 것뿐이다. 같은 `fsView`, 같은 드래그·드롭, 같은 정답 —
prop 하나로 두 개의 화법이 나온다.

평평하게 다 넣지 않는 이유는 위에 적었다. 영수증_0723이 내 기기에 있어야 한다.

## PC 전용 기능의 치환

정답 문자열은 **하나도 바뀌지 않는다.** 테스트가 강제하는 불변 규칙이 유지된다.

| PC 기능 | ask | 폰에서 | 판정 |
|---|---|---|---|
| **인쇄/복합기** | 12 | 복합기가 이미 웹페이지(192.168.10.9)다. 브라우저로 그대로. 접수번호 `P-1042` 동일 | 거의 공짜 |
| **hosts** | 4 | 설정 → 와이파이 → 사설 DNS. 같은 파일을 이름→주소 행으로 편집 | 깔끔, 오히려 더 그럴듯 |
| **cmd** | 10 | 설정 → 휴대전화 정보. `hostname`→기기 이름 `AR-PC-2104`, `ipconfig`→IP | 깔끔 |

`store.js:1401`의 hosts 파서는 "주소, 공백, 이름"만 읽고 어떤 UI가 썼는지
상관하지 않는다. `Notepad.jsx`가 hosts 하나만 편집 허용하는 구조(33줄 주석)도
그대로 살아 있다.

인쇄 힌트 중 "PC 주소는 ipconfig로 확인" 한 줄만 폰용 변형이 필요한데, 힌트는
JSON에 있으므로 **코드가 아니라 콘텐츠 작업**이다.

## 디자인

### 왜 깔끔한가

회사 PC는 촘촘하고 촌스럽다 — `#2f6fd0` 파랑, 12.5px, 관리 앱들. 폰은 조용하고
매끈하다. 이건 미감이 아니라 **대비 장치**다. 기기가 아름다울수록 그 안의
영수증과 부고가 서늘해진다.

### 색

기존 셸의 파랑(`#2f6fd0`)을 **의도적으로 버린다.** 그건 회사 시스템의 색이다.

```
--p-ink      #10131a   본문·제목 (순검정 아님)
--p-bg       #f7f8fa   화면 바탕
--p-surface  #ffffff   카드·리스트
--p-line     #e6e8ed   경계선 1px
--p-mute     #8b909c   보조 텍스트
--p-accent   #3d4a5c   강조 — 채도 낮은 슬레이트
```

**흔한 선택은 밝은 액센트다. 여기서는 채도를 거의 뺀다.** 이 폰은 즐거운 기기가
아니다. 색은 딱 두 곳에서만 산다 — 갤러리 사진, 그리고 읽지 않은 알림 점
(`#e2564d`). 그래서 **사진이 화면에서 유일하게 색을 가진 것**이 된다.

관측하면 사라지는 사진들의 게임이므로, 이 절제가 서사에서 직접 나온다.

### 타이포

```
디스플레이  'Pretendard', -apple-system, 'Malgun Gothic'   600   잠금 시계 64px / -2
본문        같은 계열                                       400   15px / 1.6
데이터      'SF Mono', Consolas, monospace                  400   12px  IP·기기명·시각
```

데스크톱은 'Segoe UI' 14px이다. 폰은 **15px**로 키운다. 터치 기기의 최소
가독선이고, 밀도를 낮추는 것 자체가 "다른 물건"이라는 신호다.

### 레이아웃

```
┌─────────────────┐          ┌─────────────────┐
│ 9:41    ▮▮▮ 87% │  상태바   │ 9:41    ▮▮▮ 87% │
├─────────────────┤  40px    ├─────────────────┤
│                 │          │ ‹  AR톡         │  앱 헤더 52px
│  ▢  ▢  ▢  ▢    │          ├─────────────────┤
│ 사진 파일 AR톡 톡톡│  4열     │                 │
│                 │  62px    │  (기존 앱 그대로)  │  .phone-body
│  ▢  ▢  ▢  ▢    │  r18     │                 │  overflow:auto
│메일 브라우저 설정 PC│          │                 │
├─────────────────┤          ├─────────────────┤
│      ────       │  홈      │      ────       │
└─────────────────┘          └─────────────────┘
```

상태바 시각은 게임 내 시계를 쓴다(`Lock.jsx`의 `hhmm`과 동일 소스).

### 모션

전부 `transform`/`opacity`만 쓴다. 레이아웃 리플로우가 없으므로 GPU 합성만 타고,
저사양 폰에서도 60fps가 나온다. **라이브러리를 추가하지 않는다** (현재 의존성은
react·react-dom·zustand뿐).

| 동작 | 지속 | 내용 |
|---|---|---|
| 앱 열기 | 220ms | 아이콘 위치에서 `scale(.4)`→1 + 페이드 |
| 앱 닫기 | 180ms | 역방향, 아이콘 자리로 수렴 |
| 화면 밀기 | 200ms | 새 화면 X `100%`→0, 이전 화면 0→`-25%` + 딤 |
| 뒤로 스와이프 | 손가락 추종 | 놓는 순간 관성으로 완료 또는 복귀 |
| 눌림 | 90ms | `scale(.96)` + 살짝 어둡게 |
| 알림 배너 | 260ms | 상단에서 Y `-100%`→0, 4.2초 후 역방향 |

이징은 `cubic-bezier(.32, .72, 0, 1)`로 통일한다. 빠르게 출발해 부드럽게 안착하는
곡선이라 스프링 라이브러리 없이 iOS 물성에 가장 가깝다.

**지속시간이 짧은 이유:** 하루에 요청 여러 건을 오가는 게임이다. 전환이 400ms면
답답해진다. 220ms 이하로 잡고 되돌아가기는 더 짧게(180ms) 한다.

관성 스크롤과 고무줄 끝단은 `overscroll-behavior: contain` +
`-webkit-overflow-scrolling: touch`로 브라우저 네이티브를 쓴다. 공짜다.

**접근성:** 6가지 전부 기존 `@media (prefers-reduced-motion: reduce)`
블록(`shell.css:1213`)에 물려 `animation: none`으로 떨어뜨린다.

### 시그니처 — 잠금화면

데스크톱 `Lock`은 시계와 비밀번호 카드다. 폰 잠금화면은 시계 64px, 날짜, 그리고
**밤사이 쌓인 알림 스택**이다. AR톡과 메일이 카드로 겹쳐 있다.

게임을 켤 때마다 "누가 나를 찾았는가"가 먼저 보이고, 그게 그날의 요청으로
이어진다. 데스크톱에는 없는, 폰에만 있는 진입이다.

비밀번호는 그대로 `2104`(사번 뒤 4자리), 힌트도 화면에 남는다 — 잠긴 채 막히는
플레이어가 없어야 한다는 기존 원칙 그대로다.

## 세이브

`SAVE_KEY = 'windowsEx.save'` 하나를 공유한다. 폰에서 하던 걸 PC에서 이어서 한다.
같은 사람의 두 기기라는 설정과 맞고, 추가 구현이 사실상 없다.

## 이번 범위

**포함** — 새 파일 5개, 두 셸이 같은 게임을 그리는 것, 폰 잠금화면, 화면 스택과
홈 복귀 세 경로, 물리 뒤로가기 가로채기, 셸 전체 모션 6종, 세이브 공유,
그리고 뷰포트 분기·스택·홈 복귀 테스트.

**제외** — 다음 라운드에서 실제로 띄워보고 정한다.

- 설정(기기 정보·와이파이) 치환 앱
- 앱 34개 개별 내부 손질
- **시트 셀 편집.** 한글/시트가 70개 ask에 걸려 있고 360px에서 셀 편집은 좁다.
  전용 전체화면 셀 편집기를 만들지, 해당 요청을 회사 PC 뷰로 보낼지는 눈으로
  보고 정한다.

**불변** — `workday.json`, `store.js`, 목표 188개, 테스트 748개.

## 알려진 한계

**셸만으로는 7할이다.** 셸이 폰처럼 움직여도 앱 안은 여전히 데스크톱 밀도다.
12.5px 폰트와 촘촘한 표가 그대로 있다. 나머지 3할은 앱별 작업이고, 그건 셸이
돌아가는 걸 보고 나서 판단하는 게 맞다.

**`Ctrl+Alt+L`은 폰에서 안 걸린다.** 키보드 전제다. 유휴 잠금 타이머
(`idleMs: 240000`)는 정상 동작한다. 고칠 건 없다.

**엣지 스와이프는 앱 내부 스크롤과 충돌할 수 있다.** 좌측 20px에서 시작한
드래그만 인식해서 해결한다. 그래도 불안하면 v1은 버튼만 두고 제스처는 뺀다.

## 테스트

이 프로젝트의 테스트 철학은 UI가 아니라 "게임이 깨지는 방식"을 검사하는 것이다.
폰 셸에서 깨지는 방식은 **길을 잃는 것**이다.

- `useViewport`가 폭과 포인터로 올바른 셸을 고르는가
- 어느 화면에서든 홈으로 갈 수 있는가 (소프트락 없음)
