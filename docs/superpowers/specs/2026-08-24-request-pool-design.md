# 요청 풀과 무작위 배정 — 설계

2026-08-24. 첫날을 뺀 나머지 날의 요청을 매 판 다르게 뽑는다.

## 데이터

```
scenario.pool = {
  fixed: { "1": [...], ..., "5": [...] },   // 그날에 묶인 요청
  sizes: { "1":5, "2":9, "3":13, "4":17, "5":21 },
  after: { "<id>": 4 },                     // 그 날 이후에만 뽑힐 수 있음
  requests: [ { id, beat } ]                // 뽑히는 요청과 그 메신저 beat
}
```

- **고정**: 1일차 전체(5건), 그리고 각 날의 메일 과제와 그날에 묶여야 하는 것 —
  2일차 엄마·지현 부탁과 납기, 3일차 발주계획서·출력·시트·드라이브·결혼식,
  4일차 4대보험, 5일차 E마트 회신.
- **풀**: 102건. 한 판에 45건이 소비되므로 남는 57건이 다음 판을 다르게 만든다.
- **after**: 4일차 서류(정부25 확인서, D유통 문서)나 3일차 hosts 퍼즐로 열리는
  드라이브 페이지를 읽어야 하는 요청은 그 날 전에는 뽑히지 않는다.

## 뽑기

- `drawFor(scenario, day, drawn, pick)`: 이미 뽑힌 것과 `after`에 걸린 것을 뺀 뒤
  `shuffle`(Fisher–Yates, 난수원 주입 가능)해서 `sizes[day] - fixed[day].length`만큼.
- `startDay`가 그날 몫을 한 번만 뽑아 `store.drawn[day]`에 저장(PROGRESS 포함)하고,
  `beatsFor`가 그 id들의 beat를 그날 beat 뒤에 붙여 메신저로 흘린다.
- `requestsOf(scenario, day, overtime, drawn)`가 고정 + 뽑힌 것 + 야근분을 합치므로
  진행 배지·퇴근 요약·`dayDone`·권고사직 분모가 모두 자동으로 따라온다.

## 테스트 (`test/pool.test.js`)

풀이 한 판 필요량의 약 2배인지, 모든 풀 요청에 objective와 grant가 맞는 beat가 있는지,
고정과 풀이 겹치지 않는지, 1일차는 그대로인지, 200판 시뮬레이션에서 매일 정원이 차고
중복이 없는지, `after`가 지켜지는지, 30판 중 26판 이상이 서로 다른지, shuffle이 공정한지.
